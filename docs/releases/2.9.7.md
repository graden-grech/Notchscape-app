# Notchscape 2.9.7

Connected Devices brings the existing ScreenBridge Mac client into Notchscape:
Settings → Tools & Shortcuts → Connected Devices. An optional encrypted session
shares mouse and keyboard control with the compatible Windows companion.

The native Control direction picker offers Both computers (default), Mac
controls Windows, and Windows controls Mac. Direction is independent of physical
display placement. Changing it releases current input before applying the new
rule, keeping the socket and selected monitors intact. Existing v1 pairing and
enter/reject messages stay compatible. Codes/session keys remain in memory;
address/layout/direction choices use separate local preferences. No automatic
connection, cloud transport, clipboard or file sharing is enabled.

## Scope and verification

The maintainer confirmed Mac-to-Windows control. Physical Windows-to-Mac testing
is deferred until they return to the PC; source and protocol tests cannot prove
that hardware path. The earlier Windows-minimized issue remains unverified.
Exact integrated Swift/.NET tests exercise pairing, ciphertext tampering, replay,
geometry and interoperability; synthetic lifecycle tests exercise dormant setup,
cancellation, lock races, failed capture, direction changes and persistence with
fake routing, without injecting OS input. The Windows source cross-build and
platform-neutral queue tests passed in the local merge work.

Public build335 excludes Face Unlock's device-bound development helper/profile
and weights. Accounts stay disabled. The main/helper identities and Sparkle
update key are preserved. A separate local336 preview keeps the existing Face
companion and is not uploaded. Existing preferences and encrypted Face data are
not deleted. No camera, vault, password or actual remote input was operated by
the agent.

The Mac download remains Apple Development signed, not notarized. The custom
ScreenBridge protocol has not received an independent security audit and does
not provide forward secrecy. Windows elevated/secure desktops may require local
input. Intel, DisplayLink, every-theme/accessibility and reverse-control hardware
coverage are not claimed. Historical public archives/feed items remain intact.
