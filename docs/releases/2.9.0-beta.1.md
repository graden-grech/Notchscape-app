# boringNotch Custom 2.9.0-beta.1 — Accounts Preview

This is an optional testing preview, not a production account rollout. Version
2.8.3 remains the latest stable release and its automatic-update feed is unchanged.

## What's included

- Optional browser-based account sign-in and an Account settings page. The app
  still works without signing in. Session credentials stay in macOS Keychain.
- Explicit Save This Mac and Restore Cloud actions for supported appearance,
  Home layout, media-display and battery-display preferences. Cloud changes use
  revision checks to avoid silent overwrites. Automatic saves are opt-in and
  pause after restart or sign-out.
- A passkey sign-in entry point for supported email accounts, guarded
  same-account reauthentication, and simpler guidance for existing Google logins.
- A Show on external displays switch with visibly disabled dependent controls,
  without changing saved display choices or syncing hardware setup between Macs.
- Lighter native Settings surfaces and a clearer AI terminal symbol.
- Experimental locked Home dropdown: an isolated lock view replaces the normal
  menu while the Mac is locked, with an unlocked preview in Advanced settings.
  The normal menu returns after unlocking. The option remains off by default.

## Important limitations

- Real passkey enrollment/login/recovery and email/password signup/recovery have
  not completed end-to-end testing. The Google connection uses Auth0 development
  credentials; production email delivery and coordinated login-account deletion
  are not ready. Apple sign-in is deliberately unavailable.
- Delete Cloud Settings deletes the saved settings document, not the login
  identity. No admin credential is embedded in the app. Names such as `admin`
  never grant privileges; server requests are owned by validated token subjects.
- Only the allowlisted settings sync. HUD permissions, display geometry, files,
  calendar events, location, AI conversations and credentials do not sync.
- Real two-Mac conflict testing, external-display/hotplug/DisplayLink tests and
  comprehensive accessibility testing remain pending.
- Lock-screen display uses the inherited private SkyLight window integration,
  not a supported Apple lock-screen extension. Visibility and mouse interaction
  are macOS-dependent; the owner confirmed a real lock/unlock test on this Mac.
  Other macOS releases and multi-display lock transitions remain untested. This does not
  bypass authentication, add an app unlock form or unlock the Mac.

Apple silicon and macOS 14 or later. Native Liquid Glass requires macOS 26 or
later. Signed with the existing Apple Development identity and Sparkle update
key; not notarized. The installed bundle ID and path are unchanged.

Passed locally: signed-build identity/update-key checks, 107 customization and
lock/display-policy checks, 61 account-allowlist checks, sign-in callback and
cancellation tests, real SDK Keychain regressions, 9 service authentication/
isolation/concurrency tests, 43 workflow/helper tests and the service dry run.

The lock-only preview's accessibility tree and layout were inspected. The owner
confirmed the real locked dropdown works, ordinary Home returns after unlocking,
and a real volume key still shows the notch HUD. Exactly one enabled HUD event
tap was verified after cold launch, Restart HUD, closing Settings and that unlock.
Eleven stored protected appearance/display/HUD/Dock/lock-screen preferences were
unchanged. No real Sparkle update installation is claimed for this preview;
it is deliberately not added to the stable automatic-update feed. GitHub CI
outcomes and public-download verification are checked separately after upload.
