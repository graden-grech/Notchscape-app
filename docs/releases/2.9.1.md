# Notchscape 2.9.1 (290) — Product branding correction

This release corrects customer-facing product and download branding. Historical
2.9.0 and earlier archives are preserved; they are not overwritten. See the
GitHub release assets for archive checksums and verification reports.

## Changed

- Fresh downloads extract `Notchscape.app`, with a `Notchscape` executable and
  `NotchscapeHelper.xpc`; renaming only the ZIP is no longer sufficient.
- Source folders, project, scheme, installer names, onboarding, About, localized
  product names and menu accessibility labels use Notchscape.
- The publisher brand is Notchscape. No company-registration or copyright-
  registration claim is added.
- Removed unused original logo assets and welcome audio. Git history retains
  recoverable copies. Legal/source/dependency notices remain separate.
- Restart uses the current app bundle, avoiding Launch Services selecting an
  older installed/downloaded copy with the same compatibility identifier.
- New Apple Notes connections use Notchscape; explicit reconnection can adopt
  the app’s former folder without deleting notes or losing stored folder IDs.
- Optional publishing workflows target Notchscape, remain opt-in and no longer
  generate a Homebrew cask that strips quarantine.
- Release gates check the actual app filename, executable and archive contents,
  not only display metadata. Signing requirements and updater trust are kept.

## Verified locally

- Signed Release build and original app/helper identity comparison.
- Extracted archive name/metadata/code-signature checks.
- Independent archive Ed25519 verification against the trusted app’s pinned key.
- 79 Python workflow, branding, archive and policy integration tests.
- Eight Apple Notes script/parser/injection checks, without Notes access.
- Public 2.9.0 download reproduces the old app/helper product names and fails
  the new archive branding check, as expected.

## Not claimed

This release is development-signed, not Developer ID signed or notarized;
Gatekeeper assessment rejects it. It is **not fully production ready**.
Actual update/relaunch, CI and local installation/rename results are recorded
separately in release verification assets; the source/build checks above do not
claim those tests passed.

## Existing installations

Sparkle can match the new bundle by its unchanged identifier, but its stock
installer preserves an existing app’s on-disk filename. After updating, quit the
app and rename that installed copy to **Notchscape.app** once if it retains its
previous filename. Keep one installed copy; do not reset privacy permissions or
delete your settings. Fresh downloads already extract as Notchscape.app.

See [distribution readiness](../DISTRIBUTION_READINESS.md) for remaining
compatibility, hardware, rights and production-distribution blockers.
